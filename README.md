# Мой режим

Личное приложение для учёта питания, тренировок и сна: этапы «вес → переход → сила», нормы по типу дня, расход по вашим данным, заготовки, режим сна и раздел «Связи».

Все данные хранятся только на этом компьютере, в браузере. Сервера и аккаунтов нет.

## Первый запуск

Нужен Node.js 20 или новее.

```
npm install
npm run build
npm run start
```

Откройте в Chrome или Edge адрес **http://localhost:4173** и пройдите мастер настройки.

## Установка как приложение (PWA)

1. Откройте http://localhost:4173 в Chrome или Edge.
2. В адресной строке нажмите значок «Установить приложение» (монитор со стрелкой), либо выберите меню ⋯ → «Приложения» → «Установить».
3. Приложение появится в меню «Пуск» и будет открываться в отдельном окне.

После установки приложение работает **без сети и без запущенного `npm run start`**: всё нужное сохранено в браузере.

> **Важно:** данные привязаны к адресу вместе с портом. Всегда открывайте приложение по одному адресу — `http://localhost:4173` или установленным значком. Если открыть другой порт (например, `npm run dev` на 5173), там будет пустой профиль.

## Резервные копии

Раздел «Профиль и этапы» → «Хранилище и резервные копии»:

- **Выбрать папку для копий.** Копия будет сохраняться в эту папку автоматически раз в день при открытии приложения; хранятся последние 14 файлов `sport-backup-ГГГГ-ММ-ДД.json`. Удобно выбрать папку, которая синхронизируется с облаком.
- **Скачать копию** — разовая копия файлом.
- **Восстановить из файла** — полностью заменяет текущие данные данными из копии.

Если браузер попросит снова разрешить доступ к папке, наверху появится баннер с кнопкой.

## Телефон и компьютер: GitHub

Приложение публикуется на **GitHub Pages** (`https://<логин>.github.io/<репозиторий>/`) и открывается с любого устройства. Данные синхронизируются через файл `sport-data.json` в отдельном **приватном** репозитории.

Один раз:

1. Код лежит в публичном репозитории (например, `sport`). В его настройках: Settings → Pages → Source: **GitHub Actions**. После каждого `git push` в `main` workflow `.github/workflows/deploy.yml` прогоняет тесты, собирает и публикует приложение.
2. Создайте приватный репозиторий для данных (например, `sport-data`) и fine-grained токен только для него с правом **Contents: Read and write** (подробная инструкция — в приложении, «Профиль и этапы» → «Синхронизация через GitHub»).
3. На устройстве, где уже есть данные: «Профиль и этапы» → «Синхронизация через GitHub» → логин, репозиторий, токен → «Подключить». Данные уйдут в GitHub.
4. На втором устройстве откройте адрес Pages; в мастере нажмите «Уже пользуетесь приложением на другом устройстве?» и подключите тот же репозиторий — данные загрузятся. На телефоне: меню браузера → «Добавить на главный экран».

Как работает:

- Изменения отправляются через 30 секунд после правки и при сворачивании приложения, правки с другого устройства забираются при открытии и при возврате в приложение. Без сети всё работает, синхронизация догонит позже.
- Если одну и ту же запись изменили на двух устройствах, остаётся более поздняя правка. Удаление тоже доходит до другого устройства.
- Токен хранится только в браузере этого устройства: не попадает в файл данных, в резервные копии и в код.
- Каждая синхронизация — коммит в приватном репозитории, поэтому GitHub хранит всю историю данных.
- Данные привязаны к адресу: `localhost:4173` и адрес Pages — разные «устройства». Чтобы перенести данные с localhost, подключите синхронизацию сначала там, затем на Pages.

## Обновление приложения

```
npm run build
npm run start
```

Затем откройте приложение: оно обновится само. Данные при обновлении сохраняются.

## Справочник продуктов

Обычные продукты (около 250) взяты из USDA FoodData Central (SR Legacy) и переведены на русский. Список лежит в `data/foods-curated.json`: у каждого продукта есть FDC id, название, синонимы, бытовые меры и коэффициент выхода. Чтобы добавить продукт в справочник, допишите его в этот файл и пересоберите:

```
npm run build:foods
```

Скрипт один раз скачает архив USDA (~6 МБ) в `data/fdc-raw/` и запишет `public/foods.json`. Продукты в упаковке (с этикетки) добавляются прямо в приложении, раздел «Продукты».

## Для разработки

```
npm run dev          # режим разработки
npm test             # юнит-тесты логики (src/domain, src/db)
npm run lint
npx tsc -b           # проверка типов
```

Браузерные проверки в безголовом Edge или Chrome (браузер не скачивается, используется установленный):

```
npx vite --port 5199 --strictPort    # в отдельном окне
npm run e2e                          # сквозной сценарий, скриншоты и checklist.json в e2e/out

npm run build && npx vite preview --port 4199 --strictPort   # в отдельном окне
npm run e2e:offline                  # PWA: работа без сети

npm run build && npm run start       # в отдельном окне
npm run e2e:sync                     # компьютер ↔ телефон через подставной GitHub API
```

Проверки каждый раз запускаются в чистом профиле браузера и не трогают ваши данные.

Устройство проекта и решения описаны в папке `openspec/` — она хранится только локально и в репозиторий не попадает.
